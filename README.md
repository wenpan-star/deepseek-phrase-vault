
# DeepSeek 语句工坊

一个离线可用、加密存储的语句 / 提示词管理工具。零构建、零依赖、纯静态。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)

---

## 一、项目简介

**DeepSeek 语句工坊** 是一个完全运行在浏览器端的轻量级语句管理工具，用于收集、整理、分类和复用日常使用的高频提示词、代码片段、常用语句。

所有数据使用 **AES-256-GCM** 加密后写入浏览器本地存储，**不依赖任何后端服务，不上传任何数据到服务器**。整个应用零构建、零 npm 依赖，`git push` 即完成部署。

### 核心特征

- **端到端加密**：PBKDF2 派生密钥 + AES-256-GCM 认证加密，所有数据在写入 localStorage 之前完成加密
- **命令-查询分离架构**：单一数据源 + 单向数据流，所有状态变更必须通过 `commands/` 层的纯函数
- **原生 ES Modules**：零构建、零打包器、零转译，直接由浏览器加载
- **离线优先**：首次访问后可完全离线使用（除 Font Awesome 图标外，无任何外部资源依赖）
- **分类层级管理**：分类 → 标签 → 语句 三级组织结构，分类可折叠、可排序；标签跨分类迁移通过编辑模态框的分类下拉完成
- **多标签管理**：拖拽排序、双击改名、色点标识、计数徽章
- **智能搜索**：关键词 AND 匹配、正则模式、本地 / 全局作用域切换、命中高亮、拼音首字母搜索
- **可关闭的拼音首字母搜索**：默认开启；如不需要可通过设置面板关闭，节省首字母映射的计算开销
- **拼音首字母搜索**：数据由《通用规范汉字表.xlsx》生成，源码零硬编码；搜索 `zfb` 可命中「支付宝」
- **批量操作**：全选、批量删除、批量移动到指定标签
- **软删除 + 回收站**：删除语句进入回收站，可恢复；30 天自动清理，容量上限 100 条
- **设置面板**：集中管理用户偏好（当前为拼音首字母搜索开关），跨会话持久
- **更多菜单**：顶栏"更多 ▾"下拉菜单，汇集回收站、设置、快捷键帮助、关于等入口
- **导入导出完整反馈**：完整 JSON 备份（含分类、回收站与设置）；导入时精确报告被丢弃的分类 / 标签 / 语句 / 回收站条目数，让用户知情
- **滚动位置记忆**：按标签 / 全局上下文独立记忆主列表滚动位置
- **UI 状态持久化**：侧边栏展开状态、搜索关键词、正则开关等全部跨会话保留
- **分类折叠状态持久化**：折叠状态存储于 localStorage 独立键，跨会话保留但独立于 Vault
- **长文本优雅显示**：卡片默认两行截断，鼠标悬停时浮层显示全文，不改变列表布局
- **图标加载多级兜底**：Font Awesome 图标支持 4 个 CDN 依序尝试；CSS 模式下额外做字体可用性验证，避免"CSS 加载成功但图标不显示"的隐性失败
- **选择标签模态框支持分类分组**：复制 / 移动 / 恢复语句时，候选标签按分类分组显示，分组可点击标题折叠 / 展开

## 二、快速开始

### 环境要求

- 任意现代浏览器（Chrome 100+ / Edge 100+ / Firefox 100+ / Safari 16+）
- 一个本地 HTTP 服务（ESM 不支持 `file://` 协议）

### 本地运行

由于 ES Modules 不支持 `file://` 协议直接加载，需要通过 HTTP 服务启动：

方式一：Python 内置服务器

    python3 -m http.server 8080

方式二：Node.js

    npx serve

方式三：VS Code Live Server 插件

在 VS Code 中打开项目，右键 `index.html` → **Open with Live Server**。

启动后浏览器访问：

    http://localhost:8080

### 部署到静态托管

本项目为纯静态站点，可直接部署到任意静态托管平台：

- **GitHub Pages**：仓库内置 `.github/workflows/pages.yml`，推送到 `main` 分支即自动部署
- **Netlify / Vercel / Cloudflare Pages**：连接 Git 仓库，构建命令留空，发布目录设置为 `/`
- **自建服务器**：直接上传整个目录到 Nginx / Apache 的静态目录即可

> 部署到子路径时无需额外配置，因为所有资源路径均使用相对路径（`./src/...`、`./styles/...`）。

### 拼音字典维护（首次使用必读）

本项目内置的 `src/utils/pinyin-data.js` 为**初始占位版本**，只包含极少量汉字。要启用完整的拼音首字母搜索，需要从《通用规范汉字表.xlsx》生成完整数据。

**准备**：确认 `scripts/data/通用规范汉字表.xlsx` 已就位。

**一键生成**：双击项目根目录的 `build.bat`，按提示完成「生成 → 校验 → 清理 → 备份处理」。

**手动生成**：

    cd scripts/tools
    npm install --no-save xlsx
    node generate-pinyin-data.js
    node check-dict-gaps.js

生成成功后，`src/utils/pinyin-data.js` 将包含约 8105 个汉字，搜索 `zfb` 即可命中「支付宝」。

> 回滚方法：`copy /y src\utils\pinyin-data.js.bak src\utils\pinyin-data.js`
>
> 注意：`pinyin-data.js.bak` 已在 `.gitignore` 中屏蔽，不会被提交或部署。

## 三、使用指南

### 3.1 添加语句

在页面底部输入框内输入语句内容，按 `Enter` 或点击「添加」按钮即可加入当前标签。

> 当前标签下已存在相同文本时会被拒绝，并给出提示。

### 3.2 编辑语句

- **双击卡片**：直接进入编辑模式
- **点击编辑图标**：同样进入编辑模式
- 编辑框内按 `Ctrl+Enter` 或点击「保存」提交，按 `Esc` 取消

### 3.3 复制语句

- 点击卡片上的复制图标 → 内容写入剪贴板，同时累加该语句的复制计数
- 在默认语库中，语句会按**复制次数降序排列**（越常用越靠前）

### 3.4 查看长文本全文

语句卡片默认只显示**前两行**，超出部分自动截断（移动端为前 3 行）。

- **鼠标悬停**在卡片文本上约 0.15 秒 → 浮层显示完整内容
- 浮层位置自动适配视口：优先显示在卡片下方，下方空间不足时翻到上方
- 移开鼠标约 0.3 秒后自动隐藏
- 短文本（未溢出两行）不会触发浮层
- 触屏设备无 hover 语义，不启用浮层；但移动端放宽为 3 行，已能显示更多内容
- 浮层内文字可选中复制（浮层本身可交互，鼠标从卡片滑向浮层不会中断）

### 3.5 组织语句

| 操作 | 入口 | 说明 |
|---|---|---|
| 复制到其他标签 | 卡片上的分享图标 | 保留原语句，在目标标签创建副本 |
| 添加到默认语库 | 卡片上的星标图标 | 快速把非默认标签的语句收藏到默认语库 |
| 批量移动到标签 | 底部批量操作栏 | 支持一次移动多条到同一目标标签 |
| 批量删除 | 底部批量操作栏 | 需二次确认，显示前 3 条预览。删除的条目进入回收站 |
| 拖拽排序 | 卡片本身 | 仅当前标签非默认、非搜索状态下可用 |

**选择目标标签模态框的分类分组**：

当用户在「复制到其他标签」「批量移动到标签」「从回收站恢复」等场景下选择目标标签时，候选标签会**按分类分组显示**：

- 每个分类下的标签列在分类标题下方，标签缩进 12px
- 点击分类标题可**折叠 / 展开**该分组
- 分组默认展开；折叠状态**不跨会话保留**（每次打开恢复为全部展开）
- 空分类自动跳过，不占用视觉空间
- 分类顺序严格按侧边栏中的顺序（在侧边栏调整分类顺序会同步反映到选择列表）

> 折叠状态不保留是**有意的设计**：折叠是"单次打开期间的临时注意力聚焦"，与 sidebar 的"跨会话视图偏好"性质不同。前者不持久化避免"上次折叠了某分类，下次打开忘了为什么"，后者持久化避免"每次打开都要重新组织侧边栏"。

### 3.6 分类管理

侧边栏采用 **分类 → 标签** 二级结构。分类是标签的一级分组，用于把大量标签按主题组织。

| 操作 | 入口 | 说明 |
|---|---|---|
| 新建分类 | 侧边栏底部「新建分类」按钮 | 打开分类模态框，输入名称（≤ 20 字） |
| 重命名分类 | 双击分类标题 | 打开编辑模态框（默认分类不可编辑） |
| 删除分类 | 分类标题右侧的 × 图标 | 空分类直接删除；非空分类弹提示框 |
| 折叠 / 展开 | 单击分类标题 | 点击切换折叠状态，状态跨会话保留 |
| 拖拽排序 | 拖动分类标题 | 分类之间可拖拽重排（默认分类固定第一） |

> **删除非空分类的行为**：该分类下的所有标签自动移入「未分类」，**标签及其中的语句不会丢失**。删除分类只撤销一次组织决策，不破坏数据——这是有意设计，与"删除标签会级联删除语句"形成对比。
>
> **默认分类「未分类」**：不可删除、不可重命名。所有未指定分类的标签自动归入此处，包括从旧版本升级时未携带分类信息的标签。

### 3.7 标签管理

- **新建标签**：点击侧边栏底部「新建标签」按钮，在模态框内选择所属分类
- **编辑标签**：双击标签项（默认语库不可编辑）；可在模态框内修改名称、颜色、所属分类
- **删除标签**：点击标签项右侧的 × 图标（默认语库不可删除）
- **拖拽排序**：拖动标签项本身（默认语库固定首位）；**仅在同一分类内拖拽排序**，跨分类迁移通过编辑模态框完成
- **跨分类迁移**：双击标签 → 在"所属分类"下拉中选择目标分类 → 确定

> 删除标签及其下所有语句**不进入回收站**。这是有意设计：
> 删除标签的确认框已明确提示"该标签下有 N 条语句"与"此操作不可撤销"；
> 若一次删除几百条会立刻撑爆回收站（100 条上限），把之前的重要误删挤出去。
> 若用户想保留语句而删标签，正确做法是先"批量移动到其他标签"。

### 3.8 搜索

- **关键词 AND 匹配**：空格分隔的多个关键词需全部命中
- **拼音首字母搜索**：输入纯 ASCII 关键词时，除字面匹配外还会尝试整段文本的拼音首字母子串匹配
  - 例：搜索 `zfb` 可命中「支付宝」
  - 例：搜索 `qbwyg` 可命中「请帮我写一个...」
  - 中文查询会优先走字面匹配，零首字母计算开销
  - 可在**设置面板**中关闭（见 3.11）
- **正则模式**：点击搜索框内的 `*` 图标开启
- **作用域切换**：
  - 图标为 🏷️ 时：仅搜索当前标签
  - 图标为 🌐 时：搜索所有标签（命中结果显示所属标签彩色徽章）
- **清除搜索**：点击搜索框右侧的 × 图标，或按 `Esc`

### 3.9 导入 / 导出

**导出全局**：

- 生成完整 JSON 备份，包含 Vault 的全部 6 个顶层字段：
  - `categories`（分类）
  - `tags`（标签）
  - `statementsMap`（语句）
  - `recycleBin`（回收站）
  - `uiState`（会话状态）
  - `settings`（用户偏好）
- 文件名包含时间戳与统计信息（分类数 / 标签数 / 语句数）
- 导出不包含：分类折叠状态、滚动位置等设备级视图偏好

**导入全局**：

- 覆盖式导入，导入前二次确认
- 导入过程会自动归一化：
  - 补齐缺失的默认分类与默认标签
  - 丢弃 id / name 为空的分类 / 标签
  - 丢弃 id / text 为空的语句
  - 丢弃缺 id / text 或 deletedAt 无效的回收站条目
  - 非法颜色值回落为 null
  - 非法分类 id 回落为「未分类」
- **完整的丢弃数报告**：导入完成后，Toast 会精确报告"已忽略 N 个非法分类、N 个非法标签、N 条非法语句、N 条非法回收站条目"，让用户完整知晓数据变化

**导入旧档**：

- 兼容旧版纯数组格式
- 追加到当前标签
- 报告格式：新增 N 条、跳过重复 M 条、忽略无效 K 条

**错误处理的友好性**：

- **非 JSON 文件**：若文件内容不是合法 JSON，且文件名不是 `.json` 扩展名，提示会明确指出；若文件名是 `.json` 但内容损坏，提示为"文件内容不是合法的 JSON 格式"
- **结构不兼容**：JSON 合法但结构不符合本应用支持的任一格式时，提示会说明"备份格式不兼容"，并引导用户确认文件来源

### 3.10 更多菜单

点击顶栏右侧的「**更多 ▾**」按钮，展开下拉菜单，包含四个入口：

| 入口 | 说明 |
|---|---|
| **回收站** | 打开回收站面板；条目数 > 0 时，菜单项右侧显示 `(N)` 计数徽章 |
| **设置** | 打开设置面板 |
| **快捷键帮助** | 通过 Toast 提示常用快捷键 |
| **关于** | 通过 Toast 提示应用版本与架构概要 |

关闭方式（任一）：

- 点击菜单项（触发对应动作后自动关闭）
- 点击菜单外部区域
- 按 `Esc`
- 窗口大小变化
- 主列表滚动

### 3.11 设置面板

设置面板集中管理**用户偏好**（跨会话持久，与 uiState 分离）。

**打开方式**：顶栏「更多 ▾」→「设置」。

**当前支持的设置项**：

| 设置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 首字母搜索 | 开关 | 开启 | 是否启用拼音首字母回退匹配 |

**行为**：

- 开关即时生效，切换后主列表立即按新设置重新过滤
- 设置通过 `vault.settings` 持久化，跨会话保留
- 关闭首字母搜索后，纯 ASCII 关键词仅做字面匹配

### 3.12 回收站

**软删除语义**：语句"删除"（单条或批量）后进入回收站，可恢复。标签删除不进入回收站（见 3.7）。

**打开方式**：顶栏「更多 ▾」→「回收站」。

**面板功能**：

| 操作 | 入口 | 说明 |
|---|---|---|
| 单条恢复 | 条目右侧的 ↩ 图标 | 恢复至原标签；原标签不存在时弹出标签选择（按分类分组） |
| 单条彻底删除 | 条目右侧的 × 图标 | 二次确认后永久删除 |
| 全选 / 取消全选 | 工具栏「全选」按钮 | 选择当前所有条目 |
| 批量恢复 | 工具栏「批量恢复」按钮 | 统一恢复到用户指定的目标标签（选择框按分类分组） |
| 批量彻底删除 | 工具栏「批量彻底删除」按钮 | 二次确认后永久删除 |
| 清空回收站 | 工具栏「清空回收站」按钮 | 二次确认后永久删除所有条目 |

**条目信息**：

- 复选框
- 来源标签徽章（删除时快照，标签被删后仍显示）
- 相对时间（"3 分钟前" / "2 小时前" / "5 天前" / 完整日期）
- 语句文本（两行截断，悬停可查看原文）

**自动清理规则**：

- **保留期**：30 天。超过此期限的条目在打开面板时被自动清理
- **容量上限**：100 条。超出时淘汰最旧条目（FIFO）
- **无时间戳条目**：视为"永久保留"，不参与过期清理

**恢复时的冲突处理**：

- 目标标签下已存在相同文本 → 跳过该条，**保留在回收站**
- 批量恢复时部分成功：成功的条目移出回收站，冲突的保留

## 四、键盘快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl / Cmd + K` | 聚焦搜索框 |
| `Ctrl / Cmd + /` | 聚焦新建语句输入框 |
| `Esc` | 按"模态框 → 菜单 → 浮层 → 清空搜索"优先级依次处理 |
| `Delete` | 删除已勾选的语句（需先勾选） |
| `Ctrl + Enter` | 编辑模态框内提交保存 |
| `Enter` | 底部输入框内快速添加语句 |

**Esc 优先级链（从高到低）**：

1. 确认对话框（`confirm`）
2. 编辑语句模态框（`edit`）
3. 标签模态框（`tag`）
4. 分类模态框（`category`）
5. 选择目标标签模态框（`select-tag`）
6. 设置面板（`settings`）
7. 回收站面板（`recycle-bin`）
8. 更多菜单（`more-menu`）
9. 全文浮层（`statement-list` 的 tooltip）
10. 清空搜索关键词并让输入框失焦

**select-tag 模态框的键盘支持**：

- `Tab` 键在分类标题与标签间顺序遍历
- 焦点在分类标题上时，`Enter` / `Space` 折叠 / 展开该分组（浏览器原生支持）
- 焦点在标签项上时，`Enter` / `Space` 选择该标签

> 说明：原 `Ctrl + N` 与浏览器「新建窗口」快捷键冲突，无法被页面阻止，因此改用无冲突的 `Ctrl + /`。

## 五、数据安全

### 5.1 加密方案

| 项目 | 实现 |
|---|---|
| 对称加密算法 | AES-256-GCM（认证加密，防篡改） |
| 密钥派生函数 | PBKDF2-SHA256 |
| 迭代次数 | 100,000 |
| 密钥长度 | 256 位 |
| 初始向量（IV） | 12 字节随机数，每次加密重新生成 |
| 存储格式 | `[12 字节 IV][密文 + AuthTag]` 的 Base64 编码 |

### 5.2 存储位置

| 存储介质 | 用途 |
|---|---|
| `localStorage` | 加密后的 Vault 主数据；分类折叠状态（明文） |
| `sessionStorage` | 滚动位置等瞬态 UI 状态（不含敏感数据） |

> 分类折叠状态使用独立的 localStorage 键 `ds_collapsed_categories_v1`。它不是敏感数据（仅记录"哪些分类被折叠"），因此明文存储。与 Vault 分离的原因：折叠状态是"这台设备上我看这个视图的习惯"，与数据本身无关。

### 5.3 隐私保证

- **无网络请求**：除 Font Awesome 图标与 Sortable 拖拽库的 CDN 加载外，无任何外部请求
- **无遥测**：不收集任何使用数据
- **无账号**：不需要注册、登录，数据完全存储在用户浏览器内
- **无后端**：不存在服务器端数据泄露风险

**外部资源清单**（共 6 个域名，均用于图标 / 字体 / 拖拽库）：

- **Sortable.js**：`cdn.jsdelivr.net`（拖拽排序库）
- **Font Awesome CSS/JS**：`cdnjs.cloudflare.com` / `cdn.staticfile.org` / `lib.baomitu.com` / `cdn.bootcdn.net`（依序尝试）
- **Google Fonts**：`fonts.googleapis.com` / `fonts.gstatic.com`（Inter 字体）

所有域名均在 `index.html` 的 CSP 白名单中显式声明，无任何"隐式"外部请求。

### 5.4 密钥说明

本项目使用**固定盐值 + 固定密码串**通过 PBKDF2 派生密钥，实现 **透明加密**：

- 优点：无需用户记忆密码，打开即用
- 局限：无法抵御拥有浏览器本地存储访问权限的攻击者（例如恶意扩展、物理接触设备）

> 如需抵御上述威胁，可自行修改 `src/constants.js` 中的 `ENCRYPTION_KEY_STRING`，并保管好该字符串。

### 5.5 数据备份与恢复

除应用内的导入导出功能外，`persist.js` 还实现了**解密失败保护**：

- 场景：用户的加密数据在当前环境中无法解密（例如 Web Crypto 策略变化）
- 行为：原始密文被复制到 `ds_encrypted_vault_v4_backup` 键，避免后续写入覆盖
- 提示：通过 Toast 提醒用户（每次会话仅提示一次）

## 六、架构概览

### 6.1 命令-查询分离

整个应用遵循**单一数据源 + 单向数据流**的设计：

- **唯一数据源**：`src/core/facade.js` 中维护的 `currentVault`
- **唯一写入路径**：所有变更必须通过 `dispatch(commandName, payload)` 分发到 `src/commands/` 下的纯函数
- **只读访问**：通过 `query(vault => ...)` 获取视图需要的数据
- **切片订阅**：视图通过 `subscribe('tags' | 'statements' | 'ui' | 'recycleBin', handler)` 订阅变更

**所有命令函数均为纯函数**：输入旧 Vault，输出新 Vault，绝不修改入参。

### 6.2 分层结构

    ┌────────────────────────────────────────────┐
    │  views/    视图层（DOM 渲染 + 事件派发）    │
    │    ↑ 订阅 slice / ↓ dispatch 命令           │
    ├────────────────────────────────────────────┤
    │  commands/ 命令层（纯函数，业务逻辑）        │
    │    ↑ 使用纯查询 / ↓ 通过 facade 更新状态    │
    ├────────────────────────────────────────────┤
    │  core/     核心层                          │
    │    · facade.js   —— 状态协调 + 持久化触发   │
    │    · vault.js    —— 状态形状 + 纯查询       │
    │    · persist.js  —— localStorage 读写       │
    │    · crypto.js   —— AES-256-GCM 加解密      │
    │    · fa-loader.js —— 图标多级兜底加载 +     │
    │                     字体可用性验证          │
    ├────────────────────────────────────────────┤
    │  utils/    工具层（无业务语义）             │
    │    · pinyin-data.js —— 汉字→首字母（生成）  │
    │    · pinyin.js      —— 首字母查询逻辑       │
    └────────────────────────────────────────────┘

### 6.3 Vault 顶层结构

    vault = {
        categories:    [{ id, name }],                ← 分类（一级组织维度）
        tags:          [{ id, name, color, categoryId }],
        statementsMap: { [tagId]: [{ id, text, copyCount }] },
        recycleBin:    [{ id, text, copyCount, sourceTagId, sourceTagName,
                          sourceTagColor, deletedAt, deletionSource }],
        uiState:       { currentTagId, sidebarExpanded, searchKeyword,
                         useRegex, searchScope },     ← 会话级瞬态
        settings:      { enableInitialsSearch }       ← 用户偏好，跨会话持久
    }

### 6.4 三级组织模型

    分类（category）
      │
      ├── 标签 A（tag，含 categoryId 指向所属分类）
      │     └── 语句 1、语句 2、...
      ├── 标签 B
      │     └── 语句 3、语句 4、...
      └── ...

**核心不变式**：

- 每个标签必有 `categoryId`，指向存在的分类；非法/缺失时回落到 `DEFAULT_CATEGORY_ID`
- 分类 `DEFAULT_CATEGORY_ID`（"未分类"）永远存在且位于首位，不可删、不可重命名
- `statementsMap[tagId]` 的结构与分类无关，查询路径完全不变（O(1)）

**折叠状态不进 Vault**：

折叠状态存于 `localStorage["ds_collapsed_categories_v1"]`，独立于 Vault。这是关键设计决策——折叠状态是**设备级视图偏好**（与滚动位置同性质），不是数据本身。不进 Vault 的收益：

- 零命令、零切片、零 Vault 结构扰动
- 折叠切换是 O(1) DOM 类切换，响应即时
- 与滚动位置的存储策略完全对齐

### 6.5 切片语义

| 切片 | 消费方 |
|---|---|
| `'tags'` | `sidebar.js` 的 `renderSidebar`（同时覆盖分类体系变更） |
| `'statements'` | `statement-list.js` 的 `renderStatementList`；`main.js` 的 `computeVisibleCount` |
| `'ui'` | `search-bar.js` 的 `updateSearchBarUI`；`main.js` 的 `computeVisibleCount` |
| `'recycleBin'` | `more-menu.js` 的 `updateMoreMenuBadge`；`modals/recycle-bin-modal.js` 的面板内容 |

> **为什么分类变更通知 `'tags'` 而非新增 `'categories'`**：分类是标签的组织维度，与标签同属一个数据源，侧边栏渲染一次即可完整处理。引入新切片徒增复杂度且会造成"改分类是否要刷新语句列表"的困惑。

### 6.6 持久化策略

命令可通过 `persistMode` 指定持久化行为：

| 模式 | 说明 | 适用场景 |
|---|---|---|
| `immediate`（默认）| 命令执行后立即加密写入 localStorage | 增删改等关键操作 |
| `debounced` | 400ms 防抖写入 | 搜索输入、滚动等高频变更 |
| `skip` | 完全不持久化 | 仅瞬态的调试命令 |

**竞态保护**：`persist.js` 内部维护写入队列 + 版本号，避免旧写入覆盖新写入。

### 6.7 拼音字典数据流

    scripts/data/通用规范汉字表.xlsx              ← 唯一数据源（用户维护）
                │
                ▼
    scripts/tools/generate-pinyin-data.js         ← 生成脚本（依赖 xlsx）
                │
                ▼
    src/utils/pinyin-data.js                      ← 自动生成（ES Module）
                │
                ▼
    src/utils/pinyin.js                           ← 手写逻辑（不硬编码数据）
                │
                ▼

                │
                ▼

**核心约束**：

- 源码零硬编码：任何 `.js` 文件里不出现汉字拼音数据
- 数据可独立重生成：改 xlsx → 重跑 bat → 数据立即更新
- 数据文件可回滚：首次生成时自动备份为 `pinyin-data.js.bak`

### 6.8 Font Awesome 图标加载链路

    initializeFontAwesomeLoader
        │
        ├─ 主路径：SVG JS（4 个 CDN 依序尝试）
        │     │
        │     ├─ cdnjs.cloudflare.com
        │     ├─ cdn.staticfile.org
        │     ├─ lib.baomitu.com
        │     └─ cdn.bootcdn.net
        │
        └─ 降级路径：CSS + Web Font（4 个 CDN 依序尝试 + 字体可用性验证）
              │
              ├─ 注入 <link rel="stylesheet">
              ├─ 等待 link.onload（CSS 文件加载完成）
              ├─ 调用 document.fonts.load() 主动触发字体加载
              ├─ 等待字体加载完成或超时（3 秒）
              ├─ 字体可用 → 图标渲染成功
              └─ 字体不可用 → 移除当前 <link>，尝试下一个 CDN

**关键设计**：

- **CSS 加载成功 ≠ 图标可用**：CSS 文件的 `onload` 只表示"CSS 加载完成"，不保证 CSS 引用的字体文件也加载成功。字体可用性检测是必要的二次验证。
- **字体检测失败时移除当前 `<link>`**：避免损坏的 `@font-face` 定义污染字体命名空间，导致后续 CDN 的 `@font-face` 无法正常覆盖。
- **SVG JS 成功后二次检查**：字体检测是异步的，期间 SVG JS 可能突然成功。此时放弃 CSS 分支，避免"SVG 与 CSS 双模式冲突"。

**CDN 顺序调整原因**（基于用户日志）：

- `cdnjs`（Cloudflare）全球最稳定 → 排首位
- `staticfile` 国内有良好节点 → 第二
- `baomitu` 相对稳定 → 第三
- `bootcdn` 国内偶尔超时 → 末位

## 九、常见问题

### Q1：启动后页面空白 / 控制台报错

**原因**：通过 `file://` 协议打开 `index.html`，浏览器拒绝加载 ES Modules。

**解决**：改用 HTTP 服务启动（参见「快速开始」章节）。

### Q2：图标不显示

**原因**（可能有多重）：

1. Font Awesome 的所有 CDN 都被网络环境屏蔽
2. CDN 返回的 CSS 正常，但 CSS 引用的字体文件损坏（例如 CDN 节点问题、中间网络层篡改）

**解决**：

- 项目内置**多级 CDN 兜底**（`cdnjs` → `staticfile` → `baomitu` → `bootcdn`），通常会自动切换到可用源
- CSS 模式下会额外做**字体可用性检测**：若某个 CDN 的字体损坏，会自动尝试下一个 CDN
- 若全部失败，图标会缺失但不影响功能；刷新页面可重新尝试加载
- 打开浏览器控制台，查看 `[FontAwesome]` 前缀的日志可定位问题

### Q3：拼音首字母搜索不生效

**原因**（三种可能）：

1. `src/utils/pinyin-data.js` 还是初始占位版本
2. 设置面板中关闭了"首字母搜索"
3. 关键词包含非 ASCII 字符（如中文）

**解决**：

- 若原因 1：双击项目根目录的 `build.bat`，等待生成完成。生成成功后 `src/utils/pinyin-data.js` 将包含约 8105 字
- 若原因 2：打开设置面板，开启"首字母搜索"
- 若原因 3：首字母搜索仅对纯 ASCII 关键词生效（避免中文误触发）

**验证方法**：搜索 `zfb`，若命中「支付宝」即为生效。

### Q4：数据丢失 / 找回

**原因**：清空浏览器数据、切换浏览器、使用无痕模式等。

**解决**：

- 定期使用「导出全局」功能备份数据
- 换设备或换浏览器时，通过「导入全局」恢复

### Q5：误删的语句能找回吗？

**能**。删除语句（单条或批量）后进入**回收站**，保留 30 天。

- 打开方式：顶栏「更多 ▾」→「回收站」
- 恢复方式：找到条目后点 ↩ 图标，或勾选多条后点「批量恢复」

> 注意：**删除标签**及其下所有语句不进入回收站，此操作不可撤销。详见 3.7 节。

### Q6：误删分类后标签会丢吗？

**不会**。删除分类时，该分类下的所有标签自动移入「未分类」，**标签及其中的语句完整保留**。

- 空分类：直接删除，无提示
- 非空分类：弹提示框告知"其下 N 个标签将移入未分类"，确认后删除

> 这一设计区别于"删除标签会级联删除语句"：分类只是标签的组织维度，删除分类 = 撤销一次组织决策，不破坏数据。

### Q7：分类折叠状态在哪里保存？

分类折叠状态保存在 **localStorage 独立键** `ds_collapsed_categories_v1` 中，**独立于 Vault**。

- 跨会话保留（下次打开看到相同的折叠状态）
- 新分类天然处于展开态（存储的是"已折叠集合"而非"已展开集合"）
- 清空 Vault 数据（重置全局 / 导入）**不影响折叠状态**

### Q8：标签能跨分类拖拽吗？

**不能直接拖拽**。跨分类迁移请使用**编辑标签模态框**中的"所属分类"下拉。

**为什么不支持拖拽跨分类**：

- 触屏设备拖拽体验差
- 拖拽排序已有"分类内排序"功能，跨分类再叠加会让 Sortable 交互复杂化
- 编辑模态框操作更明确，不会误触

### Q9：回收站占用空间吗？

**占用极小**。回收站容量上限 100 条，单条平均 200 字节，加密后整体远小于 localStorage 上限。

若需立即释放空间，可在回收站中「清空回收站」（二次确认）。

### Q10：大量语句后变得卡顿

**原因**：单标签内语句数量过多（> 2000 条）时，DOM 渲染与搜索都会变慢。

**解决**：

- 使用多标签拆分数据
- 避免在默认语库中堆积过多条目
- 未来版本可能引入虚拟滚动

### Q11：如何更换默认语料库？

**解决**：编辑 `src/preset.js` 中的 `getBuiltinPreset()` 返回值即可。首次访问或「重置全局」时会使用该预设。

> 预设中的标签会被自动归入「未分类」（`createVaultFromBuiltinPreset` 会为每个标签赋予 `DEFAULT_CATEGORY_ID`）。

### Q12：长文本卡片能显示多少内容？

- 桌面端默认显示 2 行，鼠标悬停后浮层展示全文
- 移动端默认显示 3 行（触屏无悬停语义，因此放宽行数）
- 短文本（不超过 2 行）不会触发浮层，无任何多余交互

### Q13：导入后为什么分类 / 标签数变少了？

**可能原因**：备份中有非法数据被自动丢弃。

**如何知情**：导入完成后，Toast 会精确报告丢弃明细，格式为：

> 导入成功：3 个分类，5 个标签，42 条语句（已忽略 2 个非法分类、1 个非法标签、3 条非法语句）

**丢弃的判定标准**：

- 分类：id 或 name 为空
- 标签：id 或 name 为空
- 语句：id 或 text 为空
- 回收站条目：缺 id / text，或 deletedAt 无效

**为什么丢弃而非报错**：完整拒绝一个备份会让用户无法恢复"大部分合法数据"。选择性丢弃 + 明确报告，让用户既保住了合法数据，又知晓问题所在。

### Q14：选择标签时为什么分类标题可以点击？

**答**：点击分类标题会**折叠 / 展开**该分组。

**用途**：当候选标签很多时，折叠掉不需要的分类可以快速缩小视觉范围。

**注意**：

- 分组默认全部展开
- 折叠状态**不跨会话保留**（每次打开选择框恢复为全部展开）
- 这与侧边栏的分类折叠状态不同——侧边栏的折叠状态跨会话保留，因为它是"持久的视图偏好"；选择框的折叠状态不保留，因为它是"单次选择的临时聚焦"

### Q15：为什么选择标签时的分类顺序与侧边栏一致？

**答**：这是**有意设计**。

选择框的分类顺序严格按 `vault.categories` 数组顺序渲染——这正是侧边栏中分类的显示顺序。这样用户在两个界面看到的分类结构一致，认知负担最低。

如果你在侧边栏拖拽调整了分类顺序，选择框的顺序会**立即同步**（下次打开选择框即生效）。

## 十、开发约定

### 10.1 不可妥协的规则

1. **视图层不得直接操作 `currentVault`**：所有状态变更必须通过 `dispatch` 命令
2. **命令函数必须为纯函数**：输入旧 Vault，返回新 Vault，绝不修改入参
3. **不得在 `views/` 层引用 `persist.js`**：持久化由 `facade.js` 统一触发
4. **所有用户可控文本必须转义**：写入 DOM 之前必须经过 `escapeHtml`
5. **常量集中管理**：所有"魔数"必须定义在 `src/constants.js`
6. **拼音数据零硬编码**：任何 `.js` 文件里不出现汉字拼音数据；数据一律由 `scripts/tools/generate-pinyin-data.js` 从 xlsx 生成
7. **模态框统一模式**：所有模态框（`views/modals/*.js`）必须实现 `openXxxModal` 与 `forceCloseXxxModal` 两个导出，后者返回布尔值供 `shortcuts.js` 的 Esc 优先级链使用
8. **Vault 顶层结构完整性**：每个命令的返回对象必须包含全部六个顶层字段（`categories` / `tags` / `statementsMap` / `recycleBin` / `uiState` / `settings`），即使命令本身不修改某字段，也必须保留引用。若遗漏会导致 Facade 替换 currentVault 后，其他模块读取到 undefined。
9. **设备级视图偏好不进 Vault**：滚动位置、分类折叠状态等"这台设备上我看这个视图的习惯"不进 Vault，使用独立的 localStorage / sessionStorage 键管理。
10. **能用原生元素表达语义时，优先用原生元素**：例如折叠交互用 `<details>` / `<summary>` 而非手写 `div` + `role="button"` + `aria-expanded` + `keydown` + `classList` + `display: none`。手写等价于重造浏览器，而原生元素自带键盘、ARIA、焦点、状态管理。

### 10.2 代码风格

- 使用 **原生 ES Modules**，不引入任何构建工具
- 所有函数与变量使用完整、语义化的英文命名，不缩写
- 使用 `const` 优先，其次 `let`，避免 `var`
- 大括号采用 **K&R 风格**（左括号不换行）
- 每个文件首行标注 `// filename: <path>`

### 10.3 提交信息规范

    <type>(<scope>): <subject>

    type: feat | fix | refactor | perf | docs | chore
    scope: core | commands | views | styles | config
